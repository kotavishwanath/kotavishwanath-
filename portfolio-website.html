About

Lead Mobile Developer with over 10 years in iOS and cross-platform development — modular, scalable apps, shipped through the full SDLC, from business requirements to App Store submission.

Since February 2022 I've been Lead Mobile Developer at Ford UK, driving mobile innovation on FordPass — the app that lets drivers remotely manage, lock / unlock and monitor their vehicles. I architect core features with Swift, SwiftUI and TCA, lead Google Maps and EV charging work including complex consent flows for vehicle location tracking, integrate Canopy, implement native WebRTC for secure real-time connectivity, and work with Web3 standards to future-proof the app. I also mentor the team, oversee complex map and route-planning features, manage remote and offshore developers, and run AI workshops.

I'm not mobile-only. My background includes backend technologies — Node.js, GraphQL and REST APIs, PHP, web services, and databases including SQLite and SQL Server — used in production at Lavu to power real-time order-status apps with React Native, Redux and Node.js. As a side project I architected and built a full-stack website with Next.js and Google Gemini Pro AI, with CI/CD pipelines, deployment on Vercel, and a custom domain via GoDaddy.

AI is part of how I work every day, not just a feature I ship. I create a reusable SKILL.md file for each task so AI workflows can be reused instead of starting from scratch, write clear instructions files for agents, and choose the best agent for each particular task. I use AI to check and write documentation and tests, assess the blast radius of my changes before shipping, review and refactor code, trace crashes and edge cases, and inside CI/CD — and I evaluate AI-generated output for correctness rather than accepting it blindly. At Ford I also run AI workshops for the team. The full breakdown is in the AI section below.

Across a decade I've shipped across very different domains: connected vehicles at Ford, GPS motorsport data analysis at RACELOGIC (Circuit Tools iOS), live news streaming at 99TV, restaurant point-of-sale at Lavu — including international fiscal receipts and payment gateways, recognised with a Spotlight Award — a BLE-connected health ecosystem at HealthKOS monitoring blood pressure, glucose and pulse, and a location-based offers app at Lexicon InfoTech. That range is why I'm strong on optimisation, memory management and debugging under real-world pressure.

I'm open to both permanent and contract lead / senior mobile roles, remote in the UK. I hold Indefinite Leave to Remain (ILR), so I have no visa dependencies and need no sponsorship.

03

AI & Agentic Workflows

AI is a working method for me — in the product, in the codebase, and in the pipeline. I ran AI workshops at Ford, integrated Google Gemini Pro into a full-stack Next.js site I built myself, and I use AI agents daily to review, test, debug and ship Swift / SwiftUI code more safely.

How I work with AI

Reusable skills. Clear instructions.
Checked outputs.

I don't start from a blank prompt each time. I create a SKILL.md file for each task so the workflow is reusable, write instructions files agents can follow reliably, pick the best agent for the particular task, and then evaluate what the AI produces — for correctness, edge cases and impact — before it ships.

AI / 01

Reusable SKILL.md & Instructions Files

I create a SKILL.md file for each task and reuse it, so proven workflows compound instead of being reinvented. Alongside that I write clear, structured instructions files for AI agents — context, constraints and steps — so they work consistently and repeatably.

AI / 02

Agent Selection & Prompt Engineering

I know which agent is best for a particular task — code, docs, testing, research or review — and route the work accordingly. I use prompt engineering: structured prompts written for consistent, repeatable results, not one-off guesses.

AI / 03

AI Code Review & Refactoring

I use AI to review pull requests, spot bugs and safely refactor Swift / SwiftUI code — improving structure and readability while protecting behaviour, with the diff checked like any other engineer's work.

AI / 04

AI-Assisted Debugging

I use AI to trace crashes, work through stack traces and failure patterns, and systematically test edge cases that are easy to miss manually — especially around state, concurrency and real-world device conditions in TCA apps.

AI / 05

Documentation, Tests & Evaluating AI Outputs

I use AI to check and write documentation and to write and check tests. Just as importantly, I evaluate AI-generated code for correctness — reading it, testing it and challenging it before it merges. That evaluation discipline is exactly what AI-training and code-review roles ask for.

AI / 06

Blast Radius & AI in CI/CD

Before shipping, I use AI to assess the blast radius of my changes — what a change touches, what it could break, and what needs extra testing. I also use AI in CI/CD pipelines, so checks, documentation and review support are part of delivery, not an afterthought.

AI / 07

AI for Accessibility & Performance

I use AI to check accessibility, performance and edge cases in apps — flagging issues across VoiceOver and Dynamic Type, slow paths, memory pressure and awkward states, so quality checks happen earlier and more thoroughly.

AI / 08

AI in the Product

This isn't only process. At Ford I run AI workshops showing the team how to use AI to improve the mobile app experience, and in my own full-stack project I integrated Google Gemini Pro AI into a Next.js website — architecture, integration, CI/CD and deployment all done by me.
